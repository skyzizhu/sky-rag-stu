# RAG

## RAG 是什么

RAG 全称 Retrieval-Augmented Generation，中文叫检索增强生成。
它的思路是：大模型先不直接回答，而是先去我的知识库里检索相关资料，
然后基于这些资料来回答问题。这样可以大大减少编造，还能标注答案出处。

## 知识切片（Chunk）

知识入库前要先切片，把长文档切成一张张知识卡片。
本项目初始参数：chunk_size 设为 600 个中文字符，overlap 设为 100 个字符。
overlap 的作用是让相邻两片之间有一段重复，防止关键句子被拦腰切断。
切片的原则是优先沿着标题和段落的自然边界切，保证每张卡片主题完整。

## Metadata 元数据

Metadata 是附着在每张知识卡片上的结构化档案信息，主要用来回答"这条知识从哪来"。
本项目保留的字段包括：来源文件、路径、领域 domain、分类 category、主题 topic、
标签 tags、章节、页码、版本号 version 和状态 status。
回答问题时展示 Metadata，我就能核对答案到底出自哪个文件的哪一页。

## 向量化（Embedding）

Embedding 是把文字变成一串数字（向量），内容越相近的文字，向量越相近。
本项目用的是本地模型 qwen3-embedding:4b，通过 Ollama 运行，不需要联网。
文档和用户的提问必须用同一个模型做向量化，否则相似度没有意义。

## 向量检索

用户提问后，系统先把问题转成向量，再去向量数据库里找出最相近的 Top K 条知识。
本项目 Top K 默认设为 5，并会展示每条结果的相关度分数。
分数越高代表这条知识跟问题越相关。
默认只检索 status=active 的知识，归档内容不参与回答。

## 后续版本计划

V2 版本计划增强检索质量：加入混合检索（向量检索加关键词检索）和重排序。
V3 版本计划做成可长期维护的个人知识系统：增量入库、版本管理、自动打标签。
