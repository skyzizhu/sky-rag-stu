# 2026-10-18 · 学习记录：检索排序体系（粗排 / 精排 / 截断）

> 今日主题：把 RAG 问答流水线里"排序"这件事彻底搞懂——
> 覆盖 B6~B11 六个节点，以及未来的阈值机制。详细规则见 realize.md 对应节点。

---

## Q1：Rerank 精排用什么做的？目标？能达到吗？好处和弊端？

- **用什么**：云端 LLM（deepseek-v4-flash）逐条打分，**不是**专用精排模型。
- **五步做法**：宽召回 10 条 → 每条截前 300 字 → LLM 按 0~10 打分（10~8 直接回答 / 7~4 主题相关 / 3~0 无关）→ 校验排序 → 全部交给下游。
- **目标**：粗排只看文字和指纹，精排"读懂内容"——判断的是**是否真的回答了问题**。
- **能达到**：理解内容排序 ✅；未完全达到：打分抖动、偶发误判、效果未量化。
- **好处**：理解内容 / 宽召回精选 / 零新依赖 / 优雅降级（失败回退粗排）/ 完全可观测 / 可开关。
- **弊端**：非确定性 / 偶发误判 / 多一次 LLM 调用（1~3s + 费用）/ 300 字截断失真 / 非真 cross-encoder / 列举题天然吃亏（靠计数扩容补救）。

## Q2：精排 = LLM 判断每张卡片与问题的关联性，然后排序？

✅ 核心正确。四个精确点：
1. 判断的是"**能否回答问题**"，不是"主题相关"（7~4 分档刻意压低"相关但没答案"的内容）；
2. **pointwise 逐张独立打分**，卡片之间不两两比较（业界还有 pairwise/cross-encoder，更准更贵）；
3. 每张卡只看**前 300 字**；
4. 排序后还要过 B11 的去重 / 多样性 / Top K，不是直接定稿。

## Q3：业界的精排是不是大多不用 LLM，而用专门的精排模型？

**是。** 主流是专用 cross-encoder 模型：`bge-reranker`（BAAI）、`Cohere Rerank`、`jina-reranker`、`Voyage rerank`。

- 更快（毫秒级 vs 秒级）、更稳（同输入同分数）、更准（专门训练）、本地跑零 API 费、能处理长文档。
- LLM 重排的流派价值：**零新增依赖**（已有 LLM 直接当裁判）+ 过程完全透明。
- 我们选 LLM 是**学习项目 + 成本优先的合理取舍**；`rerank()` 接口已预留替换位。

## Q4：向量库已经是语义判断了，为什么还要精排？

**本质：双塔（分别编码再比较）vs 交叉编码（问题 + 文档放一起看）。**

- 向量检索：问题、卡片**各自**编码成向量再比余弦——看不到逐字交互。
- 精排：把「问题 + 卡片」**一起**喂给模型判断。

三个向量检索解决不了的场景：
1. **主题相关 ≠ 有答案**——只有栏目标题的卡片和提问语义极像，但没答案；
2. **否定 / 限定词分不清**——"不支持 OCR"和"支持 OCR"向量距离很近；
3. **ANN 近似本身不精确**——HNSW 是近似搜索，召回里混着噪音。

比喻：向量检索 = 按主题索引找书；精排 = 逐页翻读确认有没有那个数字。
流水线语言：**B6~B8 = 海选（宽、快、便宜、不精确）；B10 = 复试（窄、慢、贵、精确）**。

## Q5：真正的精排模型会截断吗？业界怎么做？

会截，但依据是**模型架构的 token 上限**（不是像我们这样为省 API 费手工定 300 字符）：

| 模型 | 输入上限 |
|---|---|
| bge-reranker-base | 512 tokens |
| bge-reranker-v2-m3 | 8192 tokens |
| Cohere Rerank 3 | 4096 tokens |

做法：问题 + 文档拼成一条序列共享预算；超长时常**保留开头 + 结尾**（答案常在两端）。
我们 600 字的卡片换 bge 后反而保留更完整（600 字 ≈ 600 tokens < 512~8192，视模型而定）。

## Q6：B8 / B9 / B10 的 Top K 分工？

- **B8**：两路各取 10（合计最多 20）→ RRF 融合去重 → **第一次截断到 10**；
- **B9**：只汇总这 10 条并编号，**不排序不截断**（交接节点）；
- **B10**：只**重排**这 10 条，**不截断**（全部交给下游）；
- **B11**：**第二次截断**：去重 + 多样性 + Top K → 最终 5 条。

完整数字链：**155 张 → 20 → 10 → 10（重排）→ 5**。

## Q7：B11 的 10→5，业界怎么做？

- 业界标准：**事实型问答精排后保留 Top 3~5**；多跳 / 列举 / 总结类 **5~10 或动态**。
- 核心共识：**"宽召回（20~100 条）+ 窄上下文（3~5 条干净内容）"**。
- 为什么不越多越好：**"lost in the middle"**——LLM 对上下文中间部分的信息利用率明显偏低，塞太多反而稀释注意力。
- 固定小 K 对列举/多跳题是坑（业界名言"top-5 rerank 是覆盖率坟场"）——我们用**计数意图自动扩容（5→10）**解决了同一问题，与业界演进方向一致。
- 我们唯一落后业界：**按分数阈值动态截断**（LLM 打分不稳做不了）→ 见 Q8。

## Q8：「分数阈值替代固定 K」是什么意思？

- **固定 K = 按名额录取**（数量定死，质量随缘）；**阈值 = 按分数线录取**（质量定死，数量随缘）。
- 例子：知识库里只有 2 张卡真相关时——固定 Top 5 会塞进 3 张噪音；阈值只进那 2 张，上下文更干净。
- **为什么现在做不了**：阈值成立的前提是分数稳定可信。LLM 打分**随机**（同卡今天 8 明天 6，分数线形同虚设）且**跨问题不可比**；还实测给含答案的卡片打过 0 分——阈值模式下就是答案直接丢失。
- **reranker 为什么可以**：在海量"问题-文档-相关度标注"上专门训练，输出校准过的分数——同输入同输出，0.9 分在任何问题上都代表高度相关。
- **已写入 realize.md B10.5**（预留计划）：含 7 步实施清单、业界阈值设定方式（固定值 / 分位数 / 动态）、"阈值 + 固定 K 组合护栏"方案。前提是先完成 B10.4 的 reranker 模型接入。

## Q9：粗排是哪一个节点做的？

**不是一个节点，是 B6 + B7 + B8 三个节点协作**：

- **B6** 向量通道：按余弦相似度排序 → 通道内 Top 10
- **B7** 关键词通道：按 BM25 打分排序 → 通道内 Top 10
- **B8** 融合：两份排名合成统一顺序（RRF）→ **粗排到此结束**
- **B9** 召回 Chunk：只汇总编号，**不排序**（交接节点）

判断标准：排序依据是否"理解内容"——B6/B7/B8 都只看表面信号（距离 / 词频 / 名次），B10 精排才是唯一读懂内容的环节。

## Q10：「扩宽」到底是什么意思？精排拿的是融合后的数据还是两路原始数据？

**精排拿到的是融合后的 Top 10**（去重、统一排序后的 10 条）——不是两路原始的 20 条。

**「扩宽」是检索开始前的参数决策**，不是某个节点的动作：

```
检索前：recall_k = 10        ← 扩宽 = 这个决策（参照系：最终只需 5 条）
B6 取 10 / B7 取 10          ← 服从决策
B8 融合截断 → 10             ← 服从决策（融合 Top 10 就是精排的输入）
B10 精排重排 → 仍是 10 条    ← 精排不截断（设计决定）
B11 去重/多样性 → 选 5 条    ← 最终需求
```

**数字流的正确读法**：扩宽让召回变成 10 条 → 精排重排后仍是 10 条 → B11 最终收成 5 条。
两个决定配合：① 扩宽（召回时多拿）+ ② 精排不截断——才形成"10 进精排、10 出精排、B11 选 5"的效果。

**关键推论**：向量是入库时**预计算**的（与问题无关），所以能建 HNSW 索引、毫秒级检索全库；精排必须**结合具体问题现场判断**，无法预计算——只能排在最后、只处理一小撮候选。**"预计算 vs 现计算"是两条通道速度差几个数量级的根本原因。**

## Q11：B8 的「融合」和 B11 的「合并去重」有什么关系与区别？

**两次去重，去的是两种完全不同的"重复"**：

| | B8 融合（通道去重） | B11 合并去重（内容去重） |
|---|---|---|
| 去重的对象 | **同一张卡片**被两条通道重复找到 | **不同卡片**的内容雷同（Overlap 重叠 / 重复文档 / 相似段落） |
| 判断依据 | 卡片身份（chunk_id）——**身份级去重** | 归一化后的**卡片全文对比**——**内容级去重** |
| 时机 | 精排**之前**（精排需要干净的统一候选列表） | 精排**之后**（按精排名次保留最优那份） |
| 不做的后果 | 同一张卡占两个名额 | 上下文塞重复内容，浪费 token |

**类比**：两个猎头各推 10 份简历，张三被两边都推了——HR 先把张三**合并成一份**（B8）；复试排序后发现有两份简历内容雷同——**只保留排位高的那份**（B11）。

**关系**：**不同层的两次去重，互补不重复**——B8 保证"通道身份"不重复，B11 保证"进入上下文的内容"不重复，缺一不可。

## 核心认知（一句话版）

1. **粗排 = 海选**（B6/B7/B8：快、便宜、不懂内容，从全库缩到 10 条）
2. **精排 = 复试**（B10：懂内容，判断"答没答到点上"，但只排序不淘汰）
3. **B11 = 定稿**（去重 + 多样性 + Top K，10 → 5）
4. **"语义相似" ≠ "答案相关"**——精排存在的全部意义就是补这个差值
5. **未来升级路线**：LLM 打分 → 专用 reranker（先做）→ 分数阈值替代固定 K（后做），顺序不能反
