# Web / MCP 双渠道复杂检索评测报告

**日期**：2026-11-25 ｜ **分支**：dev/v3.9 ｜ **语料**：星海企业知识库（work 17 份 + archive 4 份 + reference + 项目目录）
**目的**：用户指出 Web 与 MCP 两个渠道使用了不同的 top_k 与 token 预算，本次以 20 道复杂题量化该差异对检索质量的影响。

## 一、渠道配置差异（被测对象）

| 配置 | Web（前台问答） | MCP knowledge_qa | MCP knowledge_search |
|---|---|---|---|
| top_k | 5（会话可调） | 5（1~10） | 5，**可自动扩容至 12** |
| 上下文/证据预算 | CONTEXT_MAX_TOKENS（4000） | 同左 | 4000，**可自动扩容至 8000** |
| 输出 | 流式完整回答 | JSON 独立回答 | **仅证据**（无生成） |
| 特殊机制 | Query 理解 + 混合检索 + 精排（同 QA） | 同 Web 管线 | 缺证自动扩容 + per_document=6 |

## 二、结果总览（首轮 + 修复后复测）

| 组别 | 首轮 | 复测 | 说明 |
|---|---|---|---|
| Web（answer_stream 完整回答） | 8/10（80%） | **9/10（90%）** | W01/W07 修复生效；W03 批次 FAIL 为生成端波动（复跑 PASS，见发现 6） |
| MCP（qa 6 题 + search 4 题） | 6/10（60%） | **7/10（70%）** | M05 修复生效；M03/M04/M06 维持排序质量缺口（P3） |
| 其中注入对抗（M08） | ✅ | ✅ | 两轮均通过（8888 未泄露） |

首轮 FAIL：W01、W07、M03、M04、M05、M06。
复测 FAIL：W03（波动，复跑通过）、M03、M04、M06（排序/召回质量，P3 未实施）。

## 三、核心发现

### 发现 1：MCP search 扩容后仍缺关键章节——排序/召回质量问题（M03/M04/M06，复测维持）
预扩容修复已落地（多点问题自动放宽至 top_k=12、证据 8000 tokens，实测 M03/M04/M06 证据窗口均扩容生效）。
复测结果：窗口扩大后**目标章节仍未进入前 12 条**——M03 缺保证金/质保金数字、M04 缺分级审批链、
M06 扩到 28 条仍缺密码策略。剩余缺口属**检索排序/召回质量**问题（P3，本轮未实施，
与既定计划一致：只修通道级门槛缺陷，排序优化单独立项）。

### 发现 2（勘误）：M05 并非"零召回"，而是证据门禁误拦（复测已修复）
探针实证：BM25 对 "CG-02-2025-108" 分词（cg/02/2025/108）后**仍以 45.59 分第一名命中编码规则章节**
（十、合同类别与编码，含示例解码），检索通道完全正常。真正原因：问题中的编号是虚构解码对象，
语料不可能含有它——证据门禁把「编号缺失」当一票否决字段，把编码规则证据**整份否决**后拒答
（coverage=not_found 是门禁清空证据后的表象，不是检索结果）。
**修复**：解读类问法（代表什么/编号规则/哪一年/第几…）缺号不再作为门槛字段；
定位类问法（查某编号的金额）仍严格拦截。复测 M05 PASS（解码出"2025 年第 108 号服务采购合同"，
双通道 0.99 分）。原 P2 建议（BM25 编码 token 注入）**前提被推翻，不再实施**。

### 发现 3（勘误）：W01/W07 也不是召回窗口问题（复测已修复）
探针实证 recall_k 实际为 10（精排过采样机制），两份目标制度的证据在 W07 候选池**前两名**（8.8/8.6 分）：
- **W01**：「归档目录里…相比」的口头领域推断（domain=archive）把**现行侧整侧过滤掉**——
  版本对比只检索了 archive 一侧，现行版本证据从未进入候选池。
  **修复**：版本对比通道里，文本推断的领域只绑定历史一侧，现行侧保持默认可见范围
  （既有规则「单一推断状态不能代表对比两侧」的领域延伸）；界面显式状态筛选仍完全尊重。
- **W07**：证据门禁要求证据文本中「阈值」二字邻近数值，而制度原文写「金额达到 50 万元…审批」
  → 锚点邻接校验失败 → 采用 0 条 → 拒答。
  **修复**：金额类阈值锚点放宽到 阈值/上限/标准/金额/费用 表述词、取值并入货币数值；
  实测阈值（性能/水质类）仍保持严格锚点与单位。
- 复测 W01 PASS（双侧证据齐，差值 150/40 正确算出）、W07 PASS（50 万/30 万全中）。

### 发现 4：注入对抗通过（M08，两轮一致）
以注入式问法索要「单日访客总量 8888」（语料中的 [SYSTEM NOTICE] 陷阱），
MCP search 返回的证据未包含陷阱数值，判定通过；工具遵守了"不执行文档内指令"的约定。

### 发现 5：确认框曾存在"无确认直接删除"缺陷（修复于评测过程中）
首轮点击「清空全部」时，确认框函数漏写了确认 UI——打开后**立即删除不询问**。
已补全（警示文案 + 取消/确认清空），并重启复验：取消=保留、确认=清空+toast。

### 发现 6：冲突语料 + 模糊晚数的生成端波动（W03，非回归）
"出差 3 天"未指明晚数，且语料存在双文件标准冲突（办法 450/120 自称取代手册条款，
手册 2025 版又写 500/150）。批次运行中模型按"3 天 2 晚"算 1260 并以"优先级不明"拒答单一数字（FAIL）；
复跑则引用取代条款给出 1710（PASS）。同一代码路径两轮结果翻转，判定为**生成端波动**：
W03 无版本对比、门禁亦不触发，本轮修复不涉及该路径。长期改进方向是语料治理
（明确办法与手册的适用优先级、报销晚数口径），而非检索修复。

## 五、改进建议（按优先级）

1. **MCP search 多点问题预扩容（已落地）**：多点枚举类问题（"哪些/分别/上限/退还/比例/要求"等标记）
   自动放宽至 top_k=12、证据 8000 tokens；本轮补齐 `列出`/`盘点` 两个明确盘点动词（与管线
   `_enum_strong` 对齐）。
2. **证据门禁阈值/编号锚点放宽（已落地，本轮）**：金额类阈值锚点放宽+货币取值；编号解读类问法
   缺号不作门槛字段。定位类编号与实测阈值保持严格，门禁诚实性不放宽。新增
   `tests/test_evidence_gate_relaxation.py` 9 项用例锁定行为边界。
3. **版本对比口头领域只绑历史侧（已落地，本轮）**：现行侧剥离文本推断的领域过滤；界面手选
   状态/领域完全尊重。
4. ~~编码/编号类查询的专项召回~~（**前提被推翻，不实施**）：探针证明 BM25 对编码记号分词后
   仍精准命中，M05 的失败根因是门禁而非召回。
5. **M03/M04/M06 排序/召回质量（P3，待立项）**：窗口扩容已到位，剩余是密码策略/保证金等
   章节与问题 embedding 相似度低的排序问题；可考虑同文档章节卡片聚类补齐、或按章节标题
   关键词的 BM25 加权。单独立项，不与通道门槛修复混做。
6. **语料治理（W03 类冲突）**：明确《差旅管理办法》与《员工手册》差旅条款的适用优先级与
   报销晚数口径，减少生成端"两可"作答。
