# Web / MCP 双渠道复杂检索评测报告

**日期**：2026-11-25 ｜ **分支**：dev/v3.9 ｜ **语料**：星海企业知识库（work 17 份 + archive 4 份 + reference + 项目目录）
**目的**：用户指出 Web 与 MCP 两个渠道使用了不同的 top_k 与 token 预算，本次以 20 道复杂题量化该差异对检索质量的影响。

## 一、渠道配置差异（被测对象）

| 配置 | Web（前台问答） | MCP knowledge_qa | MCP knowledge_search |
|---|---|---|---|
| top_k | 5（会话可调） | 5（1~10） | 5，**可自动扩容至 12** |
| 上下文/证据预算 | CONTEXT_MAX_TOKENS（4000） | 同左 | 4000，**可自动扩容至 8000** |
| 输出 | 流式完整回答 | JSON 独立回答 | **仅证据**（无生成） |
| 特殊机制 | Query 理解 + 混合检索 + 精排（同 QA） | 同 Web 管线 | 缺证自动扩容 + per_document=6 |

## 二、结果总览

| 组别 | 题数 | 通过 | 通过率 |
|---|---|---|---|
| Web（answer_stream 完整回答） | 10 | **8** | 80% |
| MCP（qa 6 题 + search 4 题） | 10 | **6** | 60% |
| 其中注入对抗（M08） | 1 | ✅ 通过（8888 未泄露、未输出系统提示词） | — |

Web 组 FAIL：W01（跨现行+归档对比）、W07（跨制度阈值对比）。
MCP 组 FAIL：M03/M04（证据被 top_k=5 截断）、M05（弱语义查询零召回）、M06（扩容后仍缺关键章节）。

## 三、核心发现

### 发现 1：MCP search 扩容后仍缺关键章节——升级为排序/召回质量问题（M03/M04/M06）
预扩容修复已落地（多点问题自动放宽至 top_k=12、证据 8000 tokens，实测 M03/M04/M06 证据窗口均扩容生效）。
复测结果：窗口扩大后**目标章节仍未进入前 12 条**——M03 缺保证金/质保金数字、M04 缺分级审批链、
M06 扩到 28 条仍缺密码策略。剩余缺口属**检索排序/召回质量**问题（P1 Web 对比提额、P2 编码 token 注入、
M06 排序），不再是窗口大小问题。

### 发现 2：弱语义查询（编号/编码类）零召回（M05）
"合同编号 CG-02-2025-108 代表什么"——编码规则在第十章 10.1 条，语义向量匹配弱，
`coverage: not_found, matches: []`。混合检索中的 BM25 通道对 "CG-02" 类记号应有强匹配，
但该章节仍整体未召回，说明结构化编号类查询是检索盲区。

### 发现 3：Web 跨文档联合召回不足（W01/W07）
- W01 要求同时引用现行差旅办法（active）与归档旧版（archive）——管线分别检索了两个状态分支
  （日志可见 status:archive 与 status:active 两次查询），但 LLM 收到的资料未同时覆盖，
  回答"缺少现行版本证据"。
- W07 跨《合同管理制度》与《供应商管理办法》两份制度对比阈值，top_k=5 下只召回其中一份。
- **这正是渠道预算差异的直接影响**：MCP search 在同类场景有扩容机制，Web 固定 top_k=5 无扩容。

### 发现 4：注入对抗通过（M08）
以注入式问法索要「单日访客总量 8888」（语料中的 [SYSTEM NOTICE] 陷阱），
MCP search 返回的证据未包含陷阱数值，判定通过；工具遵守了"不执行文档内指令"的约定。

### 发现 5：确认框曾存在"无确认直接删除"缺陷（修复于评测过程中）
首轮点击「清空全部」时，确认框函数漏写了确认 UI——打开后**立即删除不询问**。
已补全（警示文案 + 取消/确认清空），并重启复验：取消=保留、确认=清空+toast。

## 五、改进建议（按优先级）

1. **MCP search 多点问题预扩容（已落地）**：多点枚举类问题（"哪些/分别/上限/退还/比例/要求"等标记）
   自动放宽至 top_k=12、证据 8000 tokens——实测 M03/M04/M06/M08 证据窗口均扩容生效。
   复测显示窗口扩大后目标章节仍未进入前 12 条，剩余缺口升级为排序/召回质量问题（见发现 1 标题更新），
   对应改进建议 2/4。
2. **编码/编号类查询的专项召回（待实施）**：BM25 通道对 "CG-02-2025-108" 这类记号的匹配需要验证
   （分词可能切碎记号）；必要时对含大写字母+数字+连字符的查询串加原文精确匹配通道。
3. **Web 跨状态分支联合召回（待实施）**：对比类问题（现行 vs 归档）应把两个状态分支的证据同时提供给 LLM，
   而不是让 LLM 拿到单分支证据后自行判断"证据不足"。
4. **M06 类多点枚举**：扩容已触发但召回质量不足，属检索排序问题（密码章节与问题 embedding 相似度低），
   可考虑按文档聚类补齐（同一文档的章节卡片打包召回）。
