# 核心业务整体验收

本轮验收以当前工作区为准，使用临时知识目录、SQLite、台账、内存 Qdrant、测试员工和真实校验的测试令牌。文件入库调用前端的规划与执行函数，Web 问答调用流式应用入口，MCP 调用实际工具实现。嵌入和贯通场景的生成使用测试替身。另用项目配置的真实模型验证了六道合成问答，发送内容只有手工构造的资料、问题和对话。未执行性能、负载和并发专项。

## 按业务链路验收

| 业务环节 | 结果 |
|---|---|
| 文件入库、物理路径、台账 | 5 份文件位于正确的项目目录或 public 目录。同名文件在两个项目中独立落盘。自动生成的 _info.md 在目录中存在，未进入台账或文档索引。 |
| 文件归属、权限及 MCP 直读 | 同一项目的三份文件分别为公开、内部和受限。三名员工在 Web 目录和 MCP 列表中看到的文件数均分别为 3、2、1。两名未获个人授权的员工用文档 ID 直读也无法取得受限文件。归属部门与文件权限独立生效。 |
| 当前版、历史版和授权修改 | 重复上传被跳过。正文变更后 1.1 生效、1.0 留作历史，可用版本条件分别取到新旧正文。不重新入库即可修改访问名单，且现行和历史版本均按新权限执行。 |
| Web、MCP 问答及引用 | 两端都引用了支持当前事实的原文。MCP 搜索取到正确项目的证据。独立 Word 样例正确识别正文声明版本 2.3，保留系统入库版本 1.0，并从显式分页的第 2 段引用证据。 |
| 业务方向和员工生命周期 | 项目改挂业务方向后，MCP 的新旧方向过滤立即反映变更。停用员工后令牌失效，重新启用后不会自动恢复旧个人授权。 |
| 审计与管理台统计 | SQLite 记录了入库、跳过和升版事件、最终文件路径、浏览器指纹、来源 IP 和业务属性。MCP 问答日志保留工具名及来源。工作台仅统计 5 份现行文档，其中 4 份挂接项目；历史版未重复计数。 |
| 文件归档、恢复 | 权限、归属部门、项目和最新正文继续可用。版本号和历史记录保留失败，见下节。 |

## 优先修复

### P1 · 归档和恢复破坏版本历史

受限文档先后入库两次。归档前索引中存在 1.0 历史版、1.1 现行版。归档后只剩标为 1.0 的归档卡片，恢复后也只剩标为 1.0 的现行卡片，其正文实际来自先前的 1.1。原 1.0 的证据无法再按历史版本读取。

归档和恢复当前都先移动源文件并删除原路径对应文档的全部卡片，再按新路径入库。现有传递机制保存了项目、类型、归属部门和可见名单，版本链未随移动保留。应先明确移动前后的文档身份、版本号和历史读取规则，再用有多个版本的受限文档回归。

在已提交的 f7186f8 上，仅对下节的两处接口问题做进程内兼容后，基线也复现了同样的 1.0 历史版消失和现行 1.1 回退为 1.0。兼容处理未修改归档、恢复和版本逻辑。

### P1 · 已提交快照单独运行时存在接口不一致

干净导出的 f7186f8 执行 import src.pipeline 时，因 src.metadata 缺少 chunk_sequence 而报错。仅在临时进程补齐该函数后，入库又在 clean_and_chunk(docs, cfg) 处失败，提交版切块函数只接受一个参数。当前工作区已有这两处实现，入库贯通测试通过。交付时需从干净检出验证应用导入与一次完整的入库。

## 回归口径与环境

| 状态 | 测试方法数 |
|---|---:|
| 通过 | 645 |
| 受 Windows 测试环境限制 | 85 |
| 其他失败 | 9 |
| 套件自带跳过 | 4 |
| 实际纳入回归 | 743 |

搜索到 761 项测试，本轮按范围排除 18 项。85 项环境限制包括 84 项 Windows 回环套接字初始化受测试隔离规则限制，以及 1 项目录文件描述符操作不受当前 Windows 环境支持。Web 前端函数、FastAPI 端点函数和 MCP 工具实现有隔离验证，浏览器交互、实际 HTTP 传输和线上数据库没有整体签收。

9 项其他失败按方法计。跨项目测试中，一组现有用例要求未知范围回退并提示，另一组仍要求立即阻断，两者需要统一验收口径。MCP 转发用例仍按旧参数断言，实际工具额外透传了默认的 history=None。版本列表的结构测试单独提取 _row 后缺少页面闭包里的 project_catalog。6 项 DOCX 用例因完整正文的换行及显式分页标记变化而失败。本轮独立 Word 样例验证了声明版本和正文页码引用，仍需更新旧格式断言并继续守住文档正文和版本声明边界。

最小兼容基线中，跨项目回退断言、MCP 参数断言和版本列表闭包夹具问题已经存在。上述 DOCX 格式断言在该基线通过，差异来自当前工作区引入的版面与分页变更。

真实模型问答单独通过 6/6，覆盖现行版本、版本差异、复合问题、证据缺失、日期边界和更正项目后的追问。这组验证的是给定合成证据时的生成与引用，整体路由和权限以隔离贯通场景为准。

## 复现

- `python -m benchmarks.core_business_audit_20261123.regression` 执行业务回归，明细在 regression.json。
- `python -m benchmarks.core_business_audit_20261123.journey` 执行四条贯通场景，明细在 journey.json。
- live_answers.json 记录真实模型在合成问题上的回答、状态与引用。
- baseline.json 保存干净检出的启动错误，以及临时兼容两处接口后的对照结果。
