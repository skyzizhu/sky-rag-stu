# Web 与 MCP 应用链路验收

本轮用 26 篇合成资料验收公开、内部和受限文档、幻灯片页码、会话项目更正、版本发布及权限撤回。性能用例覆盖 Web 流式问答、MCP 搜索和 MCP 问答，每组 12 次请求，分别运行单用户、两并发和四并发。

对照版本为已提交的 `c43f5a0` 与包含后续切片、精排和结构优化的工作区。两个版本在同一台机器上顺序运行同一份脚本，ONNX 使用 4 个 CPU 线程，每轮最多召回 6 张供精排评分。每个并发组用同一条已知证据的事实题制造可比较的突发负载。

## 测量边界

Web 计时从 `answer_stream` 入口开始，首字是首个可见增量。MCP 计时覆盖工具实现、临时员工令牌校验、证据查询、审计写入与 JSON 序列化。两端使用真实解析、入库发布、权限与版本规则、BM25、上下文组装以及本地 ONNX 精排。SQLite 和 Qdrant 使用隔离数据，向量化和云端 LLM 使用测试替身。生成替身从本轮资料中选择标记与引用，用于验证证据传递与绑定。

结果属于应用链路级验收。HTTP、浏览器渲染、在线 Ollama、云端 LLM 和 Agent 工具编排的延迟需要在服务环境单独评测。每组仅 12 次请求，表中 P95 按最近秩计算，接近该组的最慢观测值。

两版各 108 次请求均检到指定证据。Web 和 MCP 问答的生成替身引用均指向实际入选的目标证据。当前 Web 首字 P95 从单用户 3.21 秒升到四并发 9.37 秒。单用户 ONNX 推理 p50 约为 2.04–2.46 秒，检索阶段 p50 为 6.6–13.8 毫秒。当前本地精排以进程锁串行评分，四并发的主要增量来自等待同一评分锁。

两版顺序运行，同一模型的推理时间也出现较大波动。基线内单用户 Web 与 MCP 问答的 ONNX 推理中值分别为 4.84 秒和 2.97 秒。表中的版本间耗时差异只能作为本次观测，归因需要交替测量并控制候选输入和主机负载。两版均出现并发增加后精排排队这一现象。

单次冷启的 Web 首字为 5.35 秒，其中 ONNX 加载 2.54 秒，BM25 首次索引与分词初始化约 0.78 秒。相同 Web 请求命中问答缓存时，两个观测的整轮耗时为 21–23 毫秒。并发压测通过固定短历史避开问答缓存，模型与 BM25 保持热态。

## 业务与一致性结果

| 项目 | 当前工作区 |
| --- | --- |
| 公开、内部、受限文档 | 两个员工共 6 组身份与密级组合全部符合授权范围。Web 与 MCP 搜索得到相同的来源、版本及卡片集合。 |
| 页码 | 两端检索到同一份 PPTX 的第 2 张幻灯片。基线 MCP 响应缺少原始页码，当前 MCP 工具响应已包含。 |
| 新版本发布 | 暂停新版激活时，Web 返回资料变化提示并清空来源。发布完成后，两端得到新版，已热的 Web 缓存失效。显式读取旧版仍得到旧证据。 |
| MCP 与发布并发 | 将发布锁人为持有约 200 毫秒后，MCP 工具等待并在发布完成后返回新版。该次 PAT 校验 279 毫秒，正常单用户中值约 22 毫秒。 |
| 流式问答中撤权 | 已授权时产生了首段。撤权后，后续增量被拦截，结果标为失效。再次读取时两端均不返回目标文档。 |
| 项目口语更正 | 用户先说星云，再说「不，我说的是天枢项目」，随后问「这个项目的预算是多少」。Web 和 MCP 同时要求重新指定项目。 |

项目口语更正在备选语料中可稳定复现。「更正为天枢项目」和「改查天枢项目」可以绑定天枢。「不，是天枢项目」同样无法绑定。失败输入把「我说的是」或「是」并进了显式项目名称，导致已匹配到主档名的会话线索仍未采用。原始对照见 `project_correction_controls.json`。

## 精排候选数交替对照

在同一进程预热后，交替运行三种设置。每种设置验证 7 个入口与问题组合，各重复 3 次，覆盖公开证据、页码、内部及受限授权和显式项目更正。性能列仅统计有足量候选的公开巡检题，合并 Web 和 MCP 搜索的 6 次单用户观测。

| 设置 | 证据和引用验收 | 公开题整轮 p50 |
| --- | ---: | ---: |
| 6 张候选 | 21/21 | 2.07 s |
| 4 张候选 | 21/21 | 1.30 s |
| 关闭精排 | 21/21 | 51 ms |

「更正为天枢项目」在 Web 和 MCP 各通过 9 次，并取到天枢的证据。这组主要是明确事实题。四张候选可作为下一轮实验设置，复杂题、相近文档和语义召回依赖型问题仍需覆盖。复现入口为 `python -m benchmarks.e2e_workflow_audit_20261123.budget_probe`，数据见 `budget_controls.json`。

## 修复候选

1. 先修口语项目更正。增加对否定前缀后单一明确项目的测试，同时覆盖多个项目、正文提及与权限交集，避免按无关项目重写。
2. 优先测本地精排的候选数和批量推理。用事实题、复合题和卡尾证据对照 3、4、6 个候选，核对有效证据与引用后再调整预算。对串行锁积压设可观测的排队预算。
3. 单独测正在发布时的 MCP 请求。实时身份和权限读取仍是边界，令牌活动时间的同步写入可以单独评估合并或减频，缩短它与发布事务竞争的时间。

复现入口为 `python -m benchmarks.e2e_workflow_audit_20261123.run`。结果分别保存在 `current.json` 与 `baseline_c43f5a0.json`，其中包含逐请求时间、引用和控制场景。
