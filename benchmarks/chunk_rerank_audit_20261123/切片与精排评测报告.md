# 切片、精排与同文档证据评测

评测版本为 `c43f5a0`。共检查 38 个场景，14 个符合预期，24 个暴露缺陷或边界限制。优先处理切片丢字、误删正文和超预算，其次改善精排输入与同文档补片。场景刻意覆盖边界，符合预期的比例仅反映这批用例。

## 评测范围

PDF、PPTX、DOCX、XLSX、HTML、TXT 六种文件使用真实解析器和入库链路。Markdown 和跨页文本探针直接调用生产清洗与切片。所有文件和台账处于临时目录，Qdrant 为内存模式，向量使用 FakeEmbedding，BM25 使用实际实现。MCP 直接运行工具实现，验证响应和章节过滤。本地精排使用已有的 BGE ONNX 模型，LLM 精排由假响应验证输入截取与输出校验。

固定配置为 640 估算 token、80 overlap、默认 Top K 5、普通问答同文档 3 卡、上下文 4000 估算 token。补片扫描 K=1、2、3、5、10。检索命中率和精排命中率仅适用于这组隔离样本。

六种文件均正常入库。PDF、PPTX 正确定位第 2 页，DOCX 标题路径正确，短 HTML 小节合并保留标题，TXT 短标题和正文一起进入卡片。不同页的已选卡在上下文里分条引用，保留了各自物理页码。

## 召回与精排

四道已知证据定位题，BM25 的 Hit@1 为 4/4。混合链路的 Hit@1 为 2/4，Hit@3 和 Hit@5 都是 4/4。混合链路使用测试向量，数字适用于当前候选传递与 RRF 对照。独立 RRF 用例也验证了双路命中的卡片可以提升排名。

真实 ONNX 精排用六道双候选题对照。当前本地精排先取正文前 1200 字符，三道英文题的证据都从第 1420 个字符之后开始，而整卡仅约 413–423 估算 token。当前 Top 1 命中 3/6。使用同一问题、候选和模型，仅将正文读取上限放宽到能容纳整卡，Top 1 命中 6/6。可据此确认这三道题的错误发生在精排输入截断。

LLM 精排的 300 字符预览实测也漏掉卡尾证据。模型仅返回不存在的 C99 时，精排仍报告成功，实际候选分数为 -1。建议按真实模型 token 预算送入正文。超预算时保留命中处与必要前后文，并校验评分编号与有效覆盖。

## 同文档补片与 Top K

| 场景 | 实测行为 | 建议 |
| --- | --- | --- |
| 普通配额 | 同文档候选五张，采用三张，最后合成一条引用 | 分开统计原卡和引用条目。 |
| 大文档与单锚点 | 12 卡手册命中两张后展开到 12 张，13 卡手册只保留初始两张。复合题只命中一张时，12 卡手册也未补片 | 全文展开保持上限。在明确的文档和版本内，允许少量有定位依据的邻卡补齐。 |
| Top K | 固定候选顺序下，K=1、2、3、5、10 最终采用原卡数分别为 1、12、12、12、12 | 明确初始召回 K、补片配额与最终证据数量。 |
| 补片计数 | K=2、原池四张，补片后 12 张，日志计为新增十张，实际净增八张 | 区分新增卡片和原池卡片移位，按真实新增量计算配额。 |
| 枚举补片 | 同一文档与同一锚点，三轮入库后补出序号分别为 0/2/4/7、0/2/3/5、0/1/5/7 | 当前先按点位滚动截取，再按原文序号排序。应先确定原文顺序或命中邻域，再限量取片。 |
| 拼接与预算 | 真实 overlap 可成功去重，但只相同一个字符也会被误判成 overlap。首张 810 token 卡可绕过 500 token 上限 | 保存实际重叠范围与结构边界，并核对最终上下文预算。 |

普通上下文去重按文本处理，两个版本的完全相同卡片只能保留先出现版本的归属。显式版本对比走独立的分侧组装，本用例只验证共同组装时的归属丢失。

MCP 的 `get_document` 按片翻页能取到第二个片段，但片段不带物理页码。顶层 page 是卡片列表页码。`knowledge_search` 找到了 PDF 第二页证据，结果也缺物理页码。HTML 的「交通费」和「住宿费」合在一张卡后，MCP 仅检查主章节，按「住宿费」查片显示无匹配。应透传原始页码、主章节路径和覆盖章节，并让过滤识别合并的小节。

## 现有回归与修复顺序

142 项现有用例中，138 项通过、4 项失败。两项期待不同章节合成一条引用，现行逻辑在页或章节变化时保留分条。另外两项涉及枚举提取预算。四篇可同批提取的短文档在低调用预算下只提交一篇，联合批截断后的拆批用例也未进入预期路径。候选文档按篇估算调用数，实际提取允许合批，建议统一预算估算与实际批次布局。

1. 先修切片保真和预算。覆盖长句前正文、PDF 页中重复正文、章节路径、表头和最大 token。根据实际受影响的文件类型决定重切范围。
2. 再修精排输入和证据计数。分阶段报告召回、精排、原卡采用和最终引用的数量，便于定位尾部证据在哪一步丢失。
3. 最后补齐同文档稳定取片与 MCP 定位字段。用同一批题对照事实覆盖和延迟，再调整 Top K 与候选预算。

原始逐项数据保存在 `results.json`。原实现重复入库生成的 Qdrant 点位 ID 会变化，枚举探针记录的原文序号用于说明顺序依赖。

## 修复后复测

修复后 38 项均达到验收预期，另有 239 项隔离回归全部通过。超长手册用例改按有界邻卡验收，普通 Top K 用例校验最终实际采用的原卡数，复合题用例分别校验额外证据与净新增计数。

| 对照 | 修复前 | 修复后 |
| --- | --- | --- |
| 640 token 卡片的重叠用例 | 611、1212 | 611、639 |
| 本地 ONNX 两候选 Top 1 | 3/6 | 6/6 |
| 普通问答 Top K 1、2、3、5、10 | 实际采用 1、12、12、12、12 | 实际采用 1、2、3、5、10 |
| 相同文档重新入库后的截断补片 | 三次取片顺序不一致 | 三次均选择 0/1/2/3 |

追加的本地精排探针使用 3179 token 句对，修复后选中含尾部事实的 1151 token 窗口并将答案卡排在第一。六题对照还记录了逐题精排耗时。复测范围为隔离文件和本地模型。

再次复测可运行 `python -m benchmarks.chunk_rerank_audit_20261123.run`，生成 `results_after.json`。已有的切片内容和位置元数据只有在对应文件重新入库后才会刷新，存量卡片可继续按旧编号读取。Word 的页码类型标记为显式分页段，自动排版后的页码依赖实际渲染。
