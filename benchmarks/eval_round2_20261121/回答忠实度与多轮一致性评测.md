# 回答忠实度与多轮一致性评测

本轮使用 29 份合成文档、37 张卡片、临时 SQLite 和内存 Qdrant。使用配置中的 deepseek-flash，固定 BM25 检索。12 道题各跑一次 Web 共用答题管线与 MCP 问答实现，共 24 次，均返回结果。Web 路径使用会话 ID，MCP 路径传入同一份历史并注入测试账号。评测范围为应用入口和返回内容，浏览器渲染、MCP 网络传输、向量召回及精排在本轮样本范围之外。

## 结果

| 口径 | Web | MCP |
| --- | ---: | ---: |
| 答案完整且正确 | 9/12 | 10/12 |
| 有事实回答时，关键结论与限定词能由对应引用支持 | 9/10 | 10/10 |
| 缺少证据时，正文正确说明无法确认 | 3/3 | 3/3 |

逐例人工核对答案、引用编号及对应原文，并区分文档版本。同一段落中明确指向上文两条带引用的数据，可支持由这两条数据直接计算的结论。H02、H03 仅要求澄清，计入答案未通过，引用口径不适用。证据不足的三题为 F02、F04、G04。F02 的 Web 答案正确处理了实际交付日期缺失，仍因合同期限限定词前后矛盾而未通过完整答案与引用口径。24 个输出均无无效引用编号。

## 修复顺序

1. **项目追问先修 H02、H03。** 优先解析用户明确的切换和更正动作，再判断当前目标是否唯一。校验解析结果对应项目主档；同一句仍有多个真正待查项目时继续澄清。两题都在进入生成前结束，可以在共用范围解析层修复。
2. **时间限定词按原文保留。** 为“之前、当日及之前、不迟于、计划完成、实际完成”建立小组对照题。先针对合同、验收、交付等常用日期答复加强原文限定词或短引用，再多跑几次观察稳定性。本轮 Web 与 MCP 各采一次，不据此比较两端模型质量。
3. **证据不足的机器状态跟随实际答复。** F04 表明“查到了卡片”仍可能“无法回答”。MCP 应能区分已回答、部分回答和证据不足，优先覆盖已识别的明确缺项。

原始问答、引用片段和路由结果见 [answer_audit_results.json](answer_audit_results.json)。用项目虚拟环境执行 `python -B benchmarks/eval_round2_20261121/run_answer_audit.py --cloud --keyword` 可复跑。
