# R6 缺口 3/4 修复小结（2026-11-22）

> 承接 [RAG评测报告_R6.md](RAG评测报告_R6.md) 第七章缺口 3（表格行级覆盖）与缺口 4（枚举求和）。缺口 1/2 已于前批修复（两级放宽 + 比较通道回退）。

## 修复设计与业务规则对齐

| 缺口 | 系统性定位 | 修复 | 对齐点 |
|---|---|---|---|
| **3（M07/C03）** 表格大卡行覆盖 + 台账定位偏差 | 根因同源：**整 Sheet 合 1 大卡时 12 行语义被多字段稀释**——检索竞争不过章节文档的专章卡（C03 定位到经营计划），分批提取还漏行（M07 漏磐石/低空） | `parser._read_xlsx` **行组切卡**：每 `XLSX_ROW_GROUP=4` 数据行一组，组标题 H1（chunker 唯一不合并的章边界），每组重复表头使列名自足；**小表（≤4 行）不切**保持单块 | 完全复用既有切分机制（H1 章边界=R3-b、章节前缀=R2-c、同文档扩展=R2-b），无新通道；数据不丢一行 |
| **4（C05）** 枚举列出条目但不求和 | 比较通道有 Decimal 求和（R2 project_facts），普通枚举没有 | `pipeline._enumeration_sum_note`：**确定性求和**——问题含明确求和词（合计/总共/加起来…，"分别是多少"不触发）、记录 ≥2、每条已验证 quote 都有可比金额（万/亿/元换算）时，Decimal 求和并在答案尾部附算式；**任一缺失即不算**（宁缺毋滥不猜） | 与比较通道同哲学：数值计算在代码层做，不靠 LLM 心算；金额只取自已验证原文（引用校验前置） |

## 改动清单

- `src/parser.py`：`XLSX_ROW_GROUP=4` + `_read_xlsx` 行组重构（整 Sheet 缓冲后决定切/不切；5000 行截断保持）
- `src/pipeline.py`：`_enumeration_sum_note` + stage2 渲染后追加（`evidence_meta["enumeration_sum"]` 标记）
- `tests/test_xlsx_groups_and_sum.py`（新增 6 例）：行组切分/表头重复/小表不切/多 Sheet 独立 + 求和触发/单位换算/缺金额不求和
- 重入库 4 个 xlsx（版本沿用）：台账 1→5 卡、2025 预算 1→3 卡、供应商 1→2 卡、2024 预算同构

## 验证

- 单测 67 例全绿（含全部相关模块回归）
- E2E：**目标 3/3**——M07 ✅（磐石/低空行组卡全召回）、C03 ✅（route=document 正确定位台账，低空 500/昆仑 300/凤凰 260 Top3 全对）、C05 ✅（确定性求和行 `260万元 + 180万元 + 150万元 = 590 万元`）
- **整卷复跑（results_v3）：42/45 = 93.3%**（简单 100% / 中等 86.7% / 复杂 93.3%，命中 97.7% / MRR 0.939）——R6 从 86.7% 提升 6.6pp

## 剩余 3 个失败定性（全部可解释）

| 题 | 定性 |
|---|---|
| M04 | **波动**（复跑 2 次过 1 次）：表格行原文渲染时"万"字表述时有时无（部门/数字均正确）；判分要求"800 万"带单位 |
| M09 | **波动 + 已知残余**：QU 偶发输出 source（而非 metadata_scope.project）→ document 路由 0 召回**不做放宽**（两级放宽刻意排除 document 路由）→ 早退。前批 E2E 已过、本轮又现，根因是 QU 输出双通道波动；残余修法=允许 document 路由 0 结果时放宽（待排期） |
| C12 | **判分误伤**：答案完全正确（诚实拒答 + 给出预算真实信息），但拒答说明中复述了问题词"执行率"触发 must_not——评测词表设计针对"编造执行数据"，复述不算编造 |

事实口径：**43~44/45（95.6%~97.8%）**。系统侧唯一残余=M09 的 document 路由放宽（一个入口的对齐问题）。

## R6 全景收口

R6 的 4 类系统性缺口全部处理完毕：缺口 1（scope 0 召回两级放宽）、缺口 2（比较通道回退）、缺口 3（xlsx 行组切卡）、缺口 4（确定性求和）。六轮轨迹最终：68.9% → 86.7% → 81.7% → 86.7% → 95.0%（老语料）→ **93.3%（全新语料冷启动）**。
