## 二、检索评测：准确性与性能（60 题）

### 2.1 准确性总分

| 难度 | 通过 | 得分 |
|---|---|---|
| 简单 | 17/20 | 85.0% |
| 中等 | 18/20 | 90.0% |
| 复杂 | 14/20 | 70.0% |
| **合计** | **49/60** | **81.7%** |
| 检索命中率（期望来源进引用） | 55/60 | **91.7%（MRR 0.892）** |

> 其中 **2 题是判分措辞误伤、答案实际正确**（M04 答出三期 40/30/30 但判分只认"3 期"字样；M14 答出"每天增量+周日全量"但判分只认"每日增量"）。校正判分后为 **51/60 = 85.0%**。本报告按原始判分口径呈现，并如实标注。

### 2.2 失败分类（11 题 → 4 类根因）

**A. scope 误提取 → 硬拦截（4 题：S14/S15/C10/C14，均 3~10s 快速返回）**

第三轮暴露了范围识别的**新变体**：
- 台账里虚构的「磐石项目」「星辰项目」未登记主档 → QU 提取为项目范围 → 「无法识别所指定的检索范围」拦截——**但答案就在台账 xlsx 里**（台账是表格数据，不是项目主档；用户问的是"台账里"的内容）；
- 「预算超过 200 万的**项目**有哪些」→ scope 模式把「预算超过 200 万的」整段当作项目名 → 未命中主档 → 拦截（修饰语+的+项目 句式误提取）；
- 「星云和天枢两个项目的状态和风险」→ 多项目名 + 非预算/负责人问法 → 不走比较通道，落到 scope 解析 → "星云和天枢两个" 未命中 → 拦截。

与第二轮 CX01 的解析 bug 同族但**另一层**：比较通道已修，但 extract_scope 的兜底模式仍会把"<修饰语/多项目名>的项目"当字面项目名，未命中即硬拦截。对"台账里的项目"这类**表格数据中的实体**，与主档项目的边界尚无区分。

**B. 长演示文档跨页事实缺失（3 题：S18/C12/C13，检索均命中 rank1~2）**

6 页发布会 pptx 的事实分散在 slide1（日期/地点）/slide3（旗舰版参数/19999）/slide4（渠道/开售）：回答只带出了部分页的卡片（同文档上下文名额 CONTEXT_MAX_PER_DOC=3），slide1/3/4 中的部分卡片未进入组装上下文 → 模型如实说"资料未注明日期/价格只有标准版"。C11 的规格书 14 位密码条款同理（长 md 多卡，安全要求卡未进答案）。**根因：长文档 × 每文档 3 卡名额 × 精排后取舍，跨页/跨章节多事实题的上下文覆盖不足**。

**C. 版本对比触发词依赖（1 题：C15）**

「2025 版手册 vs 2022 旧版手册」未含「现在/最新/现行」字样 → version_comparison 通道未触发 → 归档意图单边生效 → 诚实拒答。第二轮修复的对比通道对措辞敏感（含"现在"即触发）。

**D. 判分措辞误伤（2 题：M04/M14）**——系统答案正确，判分别名未覆盖枚举模板「3 条记录」与「每天增量」表述。

### 2.3 亮点

- 长文档单事实检索极稳：S01~S13、M05~M20 中 26 个长文单/双事实题全部 rank1 通过；
- 跨文档矛盾/一致性题表现好：M02（笔记本 3 年 vs 4 年）、M03（密码 12 vs 14）、C16（昆仑立项与需求书指标一致性——主动答"保持一致"）、C18（归档 3 万 vs 现行 50 万）；
- 数学与聚合能力：C02（36万×3=108万 vs 36万，含倍数关系）、C03（台账 Top3：低空500/昆仑300/磐石220）、C04（状态关联负责人）全部正确；
- BM25 编号检索：REQ-KL-015 → 告警升级规则 ✅；
- 新旧手册对比（M01）、归档意图（S20/M18）稳定。

## 三、结果准确性与引用准确性（专项审计）

对全部 60 个答案做三层自动审计（`audit_citations.py`，纯后处理）：

| 指标 | 结果 |
|---|---|
| **引用完整性**（答案中所有 [n] 均对应真实来源、无越界/凭空编号） | **60/60 = 100%** |
| **事实-引用映射**（答案中出现的每个关键事实，其紧邻引用是否指向正确文档） | **61/61 = 100%**（cited_other=0，无一处错引） |
| 无引用作答 | 仅 4 题 = scope 拦截题（无来源可引，行为正确） |
| 编造来源/移用引用 | **0 例** |

**人工抽查**（多事实/数学/比较题逐句核对）：
- C01：两文档四事实全部正确，且**如实指出**昆仑需求书"未规定并发用户数"（该文档确实只写了设备并发接入——不混淆相似概念，区分准确）；
- C02：三年费用乘法、倍数对比（3 倍、多 72 万）全对，引用分别指向两份合同 [1]/[4]；
- C07：负责人/预算/模块数三事实跨两文档正确引用 [1]/[2]；
- S18/C13 的"拒答"也符合引用纪律：资料里没有（未进上下文的）事实，模型明确说没有，未编造日期。

**结论：引用机制非常可靠——答案里说什么就引什么，引什么就真是什么。11 个失败题全部是"事实没进入答案"（检索/组装/拦截层），没有一例是"事实进了答案但引错了"。**

## 四、性能（116 卡片库 · 长文本语料）

| 维度 | 结果 |
|---|---|
| 端到端（60 题均值 / p50 / 最大） | **16.0s / 16.0s / 33.2s** |
| 简单 | 13.3s（p50 12.0） |
| 中等 | 15.2s（p50 13.3） |
| 复杂 | 19.7s（p50 19.9） |
| 分阶段均值 | Query 理解 2.9~6.8s · 本地精排 7.2~8.2s · 生成 1~2s |
| 枚举通道（7 题） | 均值 16.8s（本轮无明显长尾，最大 33.2s） |
| Token 总耗 | 输入 24.7 万 / 输出 6.4 万 |

与前两轮对比：题均耗时上升（16.0s vs 上轮 16.3s 持平、第一轮 11.1s），主因是**长文档卡片更多、精排句对更长**（精排均值 7~8s）。长文本没有引发性能塌方：最大单题 33.2s，无超 1 分钟的题；检索命中 MRR 0.892 为三轮最高。
