## 一、document 路由纳入两级放宽（A-1，完成）

- **改动**（`src/pipeline.py` 放宽分支）：QU **推断**的点名文档（source 在 qu_filters）0 召回时同样进入放宽——一级去 LLM filters（含 source）重试，必要时一级补充剥离 filters 残留的推断 source；成功后顶部提示行 `scope_fallback[issue=source_relaxed]`「按文档「X」过滤未找到资料，已放宽为全库语义检索结果」。**手动/MCP 指定的 source（在 filters 里）仍不放宽**——与"手动设置不放宽"规则一致。
- **验证**：单测 88/88（新增 1 例：推断 source 放宽+提示、手动 source 不放宽双断言）。M09 的"指定范围内没有找到"早退形态消失。

## 二、M09 复查中发现的更深层边界（如实记录，需产品决策）

document 放宽后 M09 复跑 3 次呈现**新形态**：不再早退，但枚举 stage2 提取 0 条。定位链条：
- 检索层正常（台账里程碑行组卡对三种问法均 top1 命中）；
- 但 QU 输出 project scope（凤凰项目）→ 过滤后召回 = 可研+需求规格（挂了 pid 的文档，**非空**）→ 两级放宽只在 0 召回时触发，救不了"非空但缺目标文档"→ 枚举文档候选里没有台账 → 提取无里程碑。

**边界本质**：单值 `project_id` 挂接模型无法表达"全公司台账与多项目相关"。台账正文明明写着"凤凰项目 | M1 | 2026-04-30"（BM25/向量都能 top1 命中），却被项目元数据过滤挡在候选外——**元数据过滤比内容相关性更严**。可选方向（需拍板）：
1. 项目过滤时并行叠加一路"未挂项目的表格类文档"召回（改变过滤语义）；
2. 支持文档多项目关联（数据模型变更 + 后台编辑）；
3. 台账类文档登记为"跨项目文档"类型并豁免项目过滤。
