# 用户与业务流程

## 用户

单用户个人部署：产品经理本人同时承担两个角色。

| 角色 | 诉求 |
|---|---|
| 知识贡献者 | 7 类输入源存得进、存得对、不重复劳动（增量/版本自动处理） |
| 知识消费者 | 问得准、答案可信可溯源、证据不足时诚实拒答 |

## RAG 编排业务流程

### 编排一：入库（把知识存进去）
输入源（6 种文件 + 网页 URL）→ 增量判断（指纹跳过）→ 解析与文本归一化 → 元数据档案 → 清洗 → 语义切片 → 向量化 → 索引。
设计目标：**存得对、存得省、留痕可回溯**（版本管理 + 台账）。

### 编排二：检索（把相关内容找全找准）
Query 理解（改写/关键词/过滤/计数意图）→ 向量化 → 过滤 → 向量 + BM25 双路检索 → RRF 融合 → Rerank 精排 → 合并去重。
设计目标：**语义与精确匹配互补，计数问题凑齐全部条目**。

### 编排三：生成与引用（把答案说明白）
相邻补全 → 上下文组装（token 预算）→ LLM 流式生成（引用编号）→ 后处理（来源列表/拒答说明）。
设计目标：**答案可信、可溯源、不编造**。

### 编排四：评测（质量闭环）
两套考卷 × 三项指标 × 四类触发时机（改参数/改配置/修 bug/知识库更新）。
设计目标：**用量化数字守护编排质量，防止改一处坏一处**。
