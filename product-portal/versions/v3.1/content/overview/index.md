# v3.1 本版范围 —— Sky Personal RAG 的 RAG 编排设计需求

> 本文档是**产品经理视角的 RAG 编排设计需求**：把 RAG 系统本身当作设计对象，
> 定义知识如何录入（入库编排）、如何被找到（检索编排）、答案如何生成与引用（生成编排）、
> 以及如何持续验证质量（评测编排）。全部需求按**真实系统实现**整理（仓库 `main` ≥ `4e1b898`），
> 标注 ai-inferred 的条目为从实现反向归纳、待产品评审转正。
>
> 界面（Streamlit Web 应用）只是这套编排的**交互载体**，其页面结构在本版不作重点展开。

## 本版目标 ↔ 需求映射

| 编排目标 | 对应需求 |
|---|---|
| 知识"存得进"：7 类输入源统一归一化入库，增量优先、版本留痕 | FR-INGEST-001 ~ 006 |
| 检索"找得全找得准"：Query 理解 + 混合检索 + Rerank + 计数意图扩容 | FR-RTV-001 ~ 005 |
| 答案"可信可溯源"：token 预算内组装、引用对位、证据不足即拒答 | FR-GEN-001 ~ 003 |
| 质量"有尺子"：两套考卷三指标，四类时机强制回归 | FR-EVAL-001 ~ 002 |
